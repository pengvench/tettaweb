ЧТО В БАТЧЕ (5 файлов):

1) .htaccess  — ГЛАВНОЕ. 301-редиректы (канонизация хоста):
   - www.tetta-prod.ru -> https://tetta-prod.ru
   - http://tetta-prod.ru  -> https://tetta-prod.ru
   Причина: Google Search Console жаловался «Вариант страницы с тегом
   canonical» на http://tetta-prod.ru/ — все 4 варианта хоста отдавали
   200 без редиректа, Google видел дубли. После 301 все варианты
   схлопнутся в один канонический https://tetta-prod.ru.
   Кеширование статики из батч-13 сохранено без изменений.

2) filming/index.html — 4 текстовые правки (без пафоса и лишнего):
   - калькулятор: «финальная смета зависит от идеи, локаций и сложности
     продакшна» -> «финальную смету согласуем после брифа»
   - карточка «Процесс под контролем»: убрано расплывчатое «отвечаем за
     то, что получится на выходе»
   - FAQ [02]: убрано бюрократичное «Глобальный пересмотр концепции
     ... тарифицируется отдельно»
   - FAQ [06]: убрано «Без ТЗ претензий к "не то настроение" не

ПРОВЕРКА ПОСЛЕ ДЕПЛОЯ (2 минуты):
  curl -sI "http://tetta-prod.ru/" | head -1
    -> HTTP/1.1 301 Moved Permanently
  curl -sI "https://www.tetta-prod.ru/" | head -1
    -> HTTP/2 301
  curl -sIL "http://www.tetta-prod.ru/filming/" | grep HTTP
    -> одна строка 301, дальше 200 (без промежуточных прыжков)
  curl -s "https://tetta-prod.ru/filming/" | grep "согласуем после брифа"
    -> строка найдется

ЕСЛИ СТОРГОВЛОСЬ (маловероятно): браузер покажет
ERR_TOO_MANY_REDIRECTS — тогда удалите из .htaccess весь блок
<IfModule mod_rewrite.c> ... </IfModule> и включите тумблер
«Перенаправлять на HTTPS» в панели Beget (Сайты -> tetta-prod.ru).
Сайт при этом продолжит работать даже с «плохим» .htaccess,
если вдруг что-то пойдет не так — просто верните прежний файл.

ПРО GOOGLE SEARCH CONSOLE (почему пришло письмо):
  «Вариант страницы с тегом canonical» — не ошибка, а уведомление:
  Google увидел http-версию главной, понял (по canonical), что
  каноничная — https://tetta-prod.ru/, и не стал индексировать http
  отдельно. После 301-редиректа http-версия станет «Страница с
  переадресацией» — это нормальное состояние.
  ПРОВЕРЬТЕ, каким свойством вы смотрите в GSC: если свойство
  добавлено как http://tetta-prod.ru/ — удалите его и добавьте
  https://tetta-prod.ru/ (или Domain-свойство tetta-prod.ru по DNS),
  иначе статистика будет показывать «не индексируется» по всей картине.
